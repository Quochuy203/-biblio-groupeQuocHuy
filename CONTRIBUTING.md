# Guide de contribution

## Avant de coder
- Créer une issue pour décrire le travail à effectuer.
- Discuter avec l'équipe en cas de changement majeur.

## Branches
- Le nom de la branche doit suivre le format : `<type>/<n°issue>-<nom-court>` (ex: `docs/5-contributing`).

## Commits
- Écrire des messages de commit clairs et concis.

## Pull requests
- Chaque Pull Request doit être liée à au moins une Issue (`Fixes #5`).
- Au moins 1 approbation (Approve) est requise avant le merge dans `main`.

## Review
- Vérifier le code et s'assurer que les tests passent avant d'approuver.

## Definition of Done
- Le code passe tous les tests (`pytest`).
- La PR est revue et approuvée sur GitHub.

## Signaler un blocage
- Créer une Issue avec le template `blocage` si bloqué plus de 30 minutes.
